# Fleet UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make bot scope, navigation and fleet operations explicit and sync reviewed changes to origin.
**Architecture:** Preserve WPF/MVVM and BotManager. Add a pure fleet-action planner used for both preview and execution. Reuse global behaviour bindings on their own page.
**Tech Stack:** C#, WPF, .NET 10, x86, bilingual XAML resources.
**Spec:** docs/superpowers/specs/2026-10-27-fleet-ui-design.md

## Global Constraints
- Preserve existing protocol behaviour, x86 and XML docs.
- English/German resource parity; no external UI dependencies.
- Verify without mutating a live game server.

## Review Focus
- Mixed in-space/docked selection must only beam eligible bots.
- Empty or multiline command parameters must never issue malformed beam commands.
- Selection changes and filtering must not leave hidden action targets.
- Failed authentication or endpoint changes must not display stale success.
- Switching pages must not duplicate auto-scroll subscriptions.
